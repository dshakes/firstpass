Cheap until proven otherwise.

Firstpass sends every LLM request to the cheapest model first, runs your check on the real output, and escalates one rung only when that check fails. Every decision leaves a receipt anyone can re-verify.

Get started View on GitHub

A drop-in proxy for Anthropic- and OpenAI-compatible APIs. Leaving is one unset.

The problem

Model choice is a guess made before the answer exists.

Frontier prices for everyday work

Send everything to the biggest model and you pay top rate for requests a cheap model would have answered correctly.

Routers guess from the prompt

A classifier or price list picks a model before any output exists. When it guesses wrong, you find out in production.

No record of why

Either way, nothing explains why a request went where it did, or proves the answer was checked before it shipped.

How it works

Decide after the output exists, by checking it.

The question “is this good enough to serve?” can only be answered once there is an answer. So Firstpass gets one cheaply, then checks it.

  1. Cheapest model first

    Every request opens on the least expensive rung of the model ladder you configure. No classifier picks the model.

  2. Your gate checks the real output

    A gate is your definition of “good”: your test suite, a JSON schema, an LLM judge, or self-consistency across samples. A gate that errors abstains. It never passes by default.

    • tests / command
    • JSON schema
    • LLM judge
    • self-consistency
    • json-valid
    • non-empty

  3. Escalate only on failure

    Pass, and the answer is served. Fail, and Firstpass climbs exactly one rung and gates again. The expensive model is spent only when the cheap one is shown not to be enough.

receipt · example
{
  "prev_hash": "9f2c…a1b7",  // links to the decision before
  "attempts": [
    { "rung": 0, "model": "claude-haiku-4-5",
      "gates": [{ "gate_id": "tests", "verdict": "fail" }] },
    { "rung": 1, "model": "claude-sonnet-5",
      "gates": [{ "gate_id": "tests", "verdict": "pass" }] }
  ],
  "final": { "served_rung": 1 },
  "hash": "5c02…a91f"
}

Every decision is hash-chained. firstpass export writes the log; firstpass verify re-derives the chain on your own machine, with no proxy or database. Alter or reorder one record and it fails at that record. Receipts & audit →

It says no, too

Offered a cheaper model, it said no.

Add a challenger model to a route and Firstpass tests it on real traffic, graded by your own gates. A statistical test that stays valid however often you look ends in certified or halted. A halted challenger is stopped automatically. Adopting a certified one is a config change you make. It never switches models on its own.

We ran it live on real Anthropic calls, with haiku-4-5 challenging sonnet-5.

Where it fits

Strongest where “correct” is checkable.

Verification needs something to verify against. We’d rather tell you now than after you deploy.

Great fit

Output you can check

Code with tests, structured output against a schema, extraction. The gate is crisp, so every escalation is earned.

Weaker fit

Open-ended prose

The available gates are an LLM judge or self-consistency. They work, but they are weaker checks than a test suite.

Wrong tool

Nothing to check

If your output has no check at all, Firstpass has nothing to decide on. Use something else.

Why now

Cheap models got good. Agents made the bill add up.

  • Many capable models, very different prices

    For a growing share of requests, a cheaper model gives an answer that passes. The hard part is knowing which requests.

  • Agents make thousands of calls

    An agent session is a long chain of requests. Small per-call choices compound into real spend and real failure rates.

  • Spend and correctness need a paper trail

    When a model decision affects cost or quality, someone will ask why. A re-derivable receipt is an answer you can hand over.

Get started

Running in a minute. Gone with one command.

It starts in observe mode: it watches your traffic and writes receipts, and changes nothing until you turn on enforcement.

1 · Install

Homebrew
brew install dshakes/tap/firstpass-proxy
PyPI
pip install firstpass
npm · not firstpass, an unrelated package
npm i -g firstpass-proxy
prebuilt binary · macOS, Linux
curl --proto '=https' --tlsv1.2 -LsSf \
  https://github.com/dshakes/firstpass/releases/latest/download/firstpass-proxy-installer.sh | sh
Docker
docker run -p 8080:8080 -e FIRSTPASS_BIND=0.0.0.0:8080 \
  ghcr.io/dshakes/firstpass:latest
crates.io · needs Rust
cargo install firstpass-proxy

Windows and other binaries: GitHub Releases.

2 · Route your agent through it

bash
# terminal 1: observe mode changes nothing
firstpass-proxy
# terminal 2: your agent now goes through it
export ANTHROPIC_BASE_URL=http://127.0.0.1:8080
# use your agent; read receipts at http://127.0.0.1:8080/panel

No lock-in. Offboarding is unset ANTHROPIC_BASE_URL. Your keys pass straight through to your provider.
