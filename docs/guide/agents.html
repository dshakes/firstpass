Docs / Coding agents

Coding agents

Claude Code, Codex and aider are multi-turn, tool-calling clients. This page covers how Firstpass groups their turns into sessions, how it gates tool calls, what the routing-granularity eval found, and what has and has not been tested.

Point the agent at the proxy. In observe mode nothing changes and every model call gets a receipt (count_tokens metadata calls do not). In enforce mode, tool-call turns are judged by non-empty, json-valid and tool-args-valid, turns are grouped into sessions with no header, and the evidence says to keep a session on one model.

1. Point the agent at the proxy#

AgentHowEndpoint

Leaving is unsetting the variable. firstpass launch refuses to start the agent if no proxy is listening.

Observe forwards byte-identical and writes receipts. It also relays the upstream's retry-after, request-id, x-request-id, anthropic-ratelimit-* and x-ratelimit-* response headers, so an agent backs off correctly on a 429. POST /v1/messages/count_tokens is passed through and writes no receipt: it carries no routing decision, so no ladder runs.

2. Sessions without a header#

Session promotion (a session that had to escalate starts there next turn) and per-session experiments need to know which requests belong together. Firstpass picks the first of these that is present:

#SourceStored as
1x-firstpass-session headerverbatim, capped at 256 bytes
2Agent session header: x-claude-code-session-id, session_id, conversation_idagent:<hash>
3Claude Code metadata.user_id, when it embeds session_meta:<hash>
4prompt_cache_key, on agent-shaped requestspck:<hash>
5Salted hash of the conversation prefix (system or instructions, declared tool names, first user message)conv:<hash>

Derived ids are salted hashes, so a stored session id never carries raw prompt text or a raw caller id. Header lookups (1 and 2) work on every path. The body-derived ones (3 to 5) are computed only on enforce routes, where the body is already being parsed; an observe-only deployment parses no bodies.

Known ceiling Two conversations with the same system prompt, first user message and tool names share a session. The cost is an early promotion inside the promotion window, never a wrong answer. Send x-firstpass-session to separate them. Plain single-turn requests get no derived session. Source: body_session in crates/firstpass-proxy/src/proxy.rs.

3. Gating tool-call turns#

An agent step often returns a tool call and no text. Read naively that is an empty answer that fails every gate and climbs the ladder on every step. Enforce mode treats it as a tool turn when the request declared tools:

GateOn a tool turn
non-emptyPasses. An undeclared tool call with empty text fails.
json-validPasses. Text beside the call is preamble and is not parsed; the JSON contract applies to the final answer turn.
tool-args-validValidates every call's arguments against input_schema (Anthropic) or parameters (OpenAI), recursively. Fails on a tool the request did not declare, on calls when the request declared no tools, and on any schema violation. Passes when there are no tool calls.

schema and any test, judge or consistency gate still need a [[gate]] block. These built-ins check structure, not correctness: to know the code is right, gate on your tests.

Also in enforce mode: thinking and redacted_thinking blocks and tool_use are streamed back intact, stop_reason is carried across providers, and credentials are scoped. A rung's configured api_key_env is the only key used for that rung (it never falls back to the client's), and a Claude Code OAuth Bearer is accepted on the Anthropic path only.

4. A route for an agent#

toml
[[route]]
match  = {}                                    # every request; match = { agent = "…" } needs the client to send x-firstpass-agent
mode   = "enforce"
ladder = ["anthropic/claude-haiku-4-5", "anthropic/claude-sonnet-5"]
gates  = ["non-empty", "json-valid", "tool-args-valid"]

[escalation]
max_rungs_per_request = 2
session_promotion = { after_failures = 2, window = "30m" }
bash
FIRSTPASS_CONFIG=./firstpass.toml firstpass doctor   # a wrong key is a hard parse error
FIRSTPASS_MODE=enforce FIRSTPASS_CONFIG=./firstpass.toml firstpass-proxy

firstpass doctor catches wrong config keys and undefined gate ids (a misspelled tool-args-valid fails parse instead of being silently skipped). Anthropic rungs are priced built in; any other provider needs a [[price]] for every rung.

5. Where to switch models: the eval#

On 500 real SWE-bench agent runs, switching models mid-session did not pay on either ladder tested. Choosing a model per workload was far cheaper, but quality non-inferiority at 1 point was not shown.

Replay of public runs, $0, pre-registered. Haiku to opus ladder, n=500, resolved counts against always-top (384/500, $0.754 per instance). Source: agent-granularity.md.

PolicyResolved$ per instanceΔ $ per instance vs always-top

  • Mid-session escalate-and-pin costs more than always-top at equal quality on both ladders (gpt-5-mini to gpt-5.2: +$0.052 to +$0.054 per instance). With prompt caching, the top model's first call re-reads the accumulated context at the full input rate.
  • Per-session routing on a cheap/top ladder loses quality against always-top: the lower bound of the resolved-rate difference is -0.024 (haiku to opus) and -0.042 (gpt-5-mini to gpt-5.2), below the pre-registered -0.01.
  • The run-level cascade costs more. It is a proxy: per-call cascade is not identifiable from recorded whole runs, because there are no per-step gate verdicts.
  • Workload-level pool selection resolved 374/500 at $0.219 per instance against 384/500 at $0.754 (Δ $ per instance [-0.582, -0.490]; Δ resolved [-0.050, +0.008]). Non-inferiority at 1 point is not shown.
  • Exploratory, not a result: a per-repo pool selection arm resolved 382/500 at $0.122 per instance. It was added after the pre-registration and is labelled exploratory here. It needs per-repo history and was not tested on unseen repos.
Practice this implies Route per workload or route with certified selection, keep a session sticky (that is what session promotion does), and do not switch models mid-session.

Limits stated by the source: one scaffold (mini-SWE-agent, bash only), one benchmark (SWE-bench Verified, 500 instances), one run per model per instance, and a context model calibrated on 20 cheap-model trajectories, so the overhead figures are estimates. Certified selection also works across replicas: with a shared Redis log, paired mode's spend cap is cluster-wide and log errors fail closed (details).

Limits#

  • Gemini inbound protocol is unsupported. Supporting it means routes under /v1beta/models/* translating generateContent to and from OpenAI Chat, which the matrix calls non-trivial. (A Gemini upstream rung is a different thing and is supported, see Providers.)
  • The compatibility run was observe mode only. Enforce behaviour for tool turns is covered by the proxy's own tests, not by driving the real CLIs through the harness.
  • Codex was not run as a binary. Only the Responses API request shape was exercised.
  • The structural gates do not prove correctness. tool-args-valid proves a call matches its declared schema, not that it is the right call.
Point the agent at the proxy, gate tool turns with tool-args-valid, let sessions group themselves, and route per workload rather than per step. Claude Code and aider are verified in observe mode; Gemini CLI is not supported.
